# Bangladesh NID OCR Service — API Documentation

Version: 3.0.0

Fully offline OCR service for extracting and transliterating fields from
Bangladesh National ID cards. No internet access is required at runtime, and
no data leaves the host running the service.

- Base URL: `http://<host>:<port>` (default `http://0.0.0.0:8000`)
- Interactive docs: `GET /docs` (Swagger UI) and `GET /redoc` (ReDoc), auto-generated by FastAPI
- OpenAPI schema: `GET /openapi.json`
- Authentication: **none** — the service does not currently require an API key or token. Restrict network access accordingly if deployed beyond a trusted host.

---

## Endpoints

### `POST /nid/front`

Extracts fields from the **front side** of an NID card image.

**Request**

`multipart/form-data`

| Field | Type | Required | Description |
|---|---|---|---|
| `file` | file | yes | Image of the front of the NID card |

Allowed file extensions: `.png`, `.jpg`, `.jpeg`, `.bmp`, `.tiff`, `.webp`

**Response** `200 OK` — `application/json`

```json
{
  "name": "MD SAKIB HASAN",
  "father_name": "MD ABDUL KARIM",
  "mother_name": "MST RAHIMA BEGUM",
  "spouse_name": null,
  "date_of_birth": "01 Jan 1995",
  "nid_number": "1234567890123"
}
```

| Field | Type | Notes |
|---|---|---|
| `name` | string \| null | Cardholder's name, transliterated |
| `father_name` | string \| null | |
| `mother_name` | string \| null | |
| `spouse_name` | string \| null | Present only on some card formats |
| `date_of_birth` | string \| null | As printed on the card |
| `nid_number` | string \| null | |

Any field not detected on the card is returned as `null`.

**Example**

```bash
curl -X POST "http://localhost:8000/nid/front" \
  -F "file=@front.jpg"
```

### `POST /nid/back`

Extracts fields from the **back side** of an NID card image.

**Request**

`multipart/form-data`

| Field | Type | Required | Description |
|---|---|---|---|
| `file` | file | yes | Image of the back of the NID card |

Allowed file extensions: same as `/nid/front`.

**Response** `200 OK` — `application/json`

```json
{
  "address": "Village: ..., District: ...",
  "blood_group": "B+",
  "issue_date": "01 Jan 2020",
  "place_of_birth": "Dhaka"
}
```

| Field | Type | Notes |
|---|---|---|
| `address` | string \| null | |
| `blood_group` | string \| null | |
| `issue_date` | string \| null | |
| `place_of_birth` | string \| null | |

**Example**

```bash
curl -X POST "http://localhost:8000/nid/back" \
  -F "file=@back.jpg"
```

## Errors

Both endpoints return errors as JSON: `{"detail": "<message>"}`.

| Status | When it happens |
|---|---|
| `400 Bad Request` | File extension not in the allowed list. `detail` includes the rejected extension and the allowed set. |
| `422 Unprocessable Entity` | Image was readable but OCR/extraction failed in an expected way (e.g. format not recognized, no NID-shaped content found) — raised as `NIDOCRError`. |
| `500 Internal Server Error` | Unexpected failure during processing. `detail` is a generic message; specifics are written to the server log, not returned to the client. |

## Processing pipeline (per request)

1. Validate the uploaded file's extension against `allowed_extensions`.
2. Write the upload to a temporary directory.
3. Copy the upload into permanent storage (see below) — this happens regardless of whether OCR later succeeds or fails, and a storage failure does not fail the request.
4. Preprocess the image (upscaling, CLAHE contrast, denoising, adaptive thresholding).
5. Detect the NID card format.
6. Run OCR using the configured engine (`DEFAULT_OCR_ENGINE`, default `surya`).
7. Extract fields (front or back) and transliterate as needed.
8. Delete the temporary directory.

---

## Image storage

Every uploaded image is saved to permanent storage in addition to being processed:

- Location: `UPLOAD_STORAGE_DIR` env var, default `storage/uploads`
- Layout: `storage/uploads/front/` and `storage/uploads/back/`
- Filename: `<8-char-unique-id>_<original filename>` (e.g. `3f9a2b1c_front_id.jpg`) to avoid collisions/overwrites
- Saved for **all** uploads, including ones that later fail validation inside OCR processing (400-level rejections for bad extensions happen before a file is saved)
- This directory is `.gitignore`d — treat its contents as sensitive personal data (NID photos) and restrict filesystem access accordingly

## Configuration reference

Set via environment variables (loaded from `.env` at startup) or defaults in `core/config.py`:

| Variable | Default | Purpose |
|---|---|---|
| `DEFAULT_OCR_ENGINE` | `surya` | OCR engine used for all requests: `auto` (easyocr+tesseract composite), `easyocr`, `tesseract`, `paddle`, `surya` |
| `SURYA_DTYPE` | `float32` | Surya precision on GPU (`float32` or `float16`); CPU always runs `float32` |
| `UPLOAD_STORAGE_DIR` | `storage/uploads` | Permanent storage location for uploaded images |
| `INDIC_RESOURCES_PATH` | *(empty)* | Path to IndicNLP resources used for transliteration |

Non-env-configurable settings (edit `core/config.py` to change): preprocessing parameters (`upscale_factor`, `clahe_clip_limit`, `denoise_h`, etc.), `allowed_extensions`, `easyocr_languages`, `easyocr_gpu`, `tesseract_lang`, `paddle_lang`.

## Running the service

```bash
python -m nid_ocr.main
```

Runs uvicorn on `0.0.0.0:8000`. For production, run behind a reverse proxy and put the service on a private network — there is no built-in authentication.
